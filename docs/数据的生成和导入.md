# 数据生成与导入流程详解

本文档详细说明族谱管理系统中数据的生成规则、Python 脚本逻辑、SQL 导入流程及执行方式。

---

## 一、整体流程概览

```
┌─────────────────────────────────────────────────────────────┐
│  1. 生成 CSV                                                 │
│     python scripts/generate_all.py                           │
│     → sql/generated/small/{member,parent_child,marriage}.csv │
│     → sql/generated/medium/...                               │
│     → sql/generated/large/...                                │
├─────────────────────────────────────────────────────────────┤
│  2. 建库建表                                                  │
│     CREATE DATABASE gene_tree;                               │
│     python manage.py migrate                                 │
│     → 7 张业务表 + Django 系统表                               │
├─────────────────────────────────────────────────────────────┤
│  3. 导入种子数据                                               │
│     mysql gene_tree < sql/init.sql                           │
│     → 2 用户 + 1 族谱 + 6 成员                                │
├─────────────────────────────────────────────────────────────┤
│  4. 批量导入生成数据                                            │
│     mysql --local-infile=1 gene_tree < sql/import_generated.sql │
│     → 清空 → 建族谱 → LOAD DATA 导入 9 个 CSV                  │
├─────────────────────────────────────────────────────────────┤
│  5. 启动服务                                                  │
│     python manage.py runserver                               │
│     → Django 开发服务器运行                                    │
└─────────────────────────────────────────────────────────────┘
```

## 二、Python 脚本：数据生成

### 2.1 入口脚本 `generate_all.py`

编排脚本，调用核心生成器 `generate_family_csv.py` 3 次，生成 small/medium/large 三个数据集：

| 数据集  | genealogy_id | member_id 起始 | 目标人数  | 随机种子   | 起始年份 | 始祖数 |
| ------- | ------------ | -------------- | --------- | ---------- | -------- | ------ |
| small   | 1            | 10000          | 500       | 42         | 1860     | 8      |
| medium  | 2            | 20000          | 5,000     | 2026       | 1720     | 10     |
| large   | 3            | 30000          | 50,000    | 20260108   | 1600     | 12     |

**关键设计**：member_id 范围不重叠（10000+、20000+、30000+），三个数据集可共存于同一数据库，不会产生主键冲突。

每个数据集对应一个独立的族谱（genealogy），分别使用不同姓氏（如江氏、朱氏、伍氏）。

### 2.2 核心生成器 `generate_family_csv.py`（411 行）

这是数据生成的核心模块，模拟一个中国家族从始祖繁衍至今的完整过程。

#### 2.2.1 姓名生成规则

- **姓氏池**：100 个常见中国姓氏（赵、钱、孙、李、周、吴、郑、王……）
- **男性名池**：50 个常用字（伟、强、磊、军、勇、杰、涛、明……）
- **女性名池**：50 个常用字（芳、娜、秀、丽、敏、静、燕、玲……）
- **拼接规则**：名字 = 姓 + 随机 1~2 个字（从对应性别的名池中抽取）

#### 2.2.2 时间线计算

根据 `start_year`（起始年份）和目标人数，动态计算每代人的繁殖年份区间。当前年份固定为 2026。

时间跨度越大，代际越多，能容纳的总人数也越多：
- small：1860→2026（约 166 年，~5 代）
- medium：1720→2026（约 306 年，~8 代）
- large：1600→2026（约 426 年，~12 代）

#### 2.2.3 繁殖逻辑（模拟真实家族扩展）

每一代的生成过程：

1. **选择候选父母**：从当前"活跃成员"中筛选满足年龄条件的男性和女性
2. **配对结婚**：随机选择男女配对，需满足以下条件：
   - 男性年龄 22~60 岁
   - 女性年龄 20~55 岁
   - 双方年龄差 ≤ 10 岁
   - **近亲检查**：通过祖先追溯，确保 3 代以内无血缘关系（防止表亲结婚等）
3. **生育子女**：每对夫妇随机生 1~4 个孩子，孩子的性别随机决定
4. **记录关系**：生成 parent_child 记录（father/mother）和 marriage 记录

#### 2.2.4 死亡概率模型

基于当前年龄的存活概率，模拟真实的生死状态：

| 年龄区间 | 存活概率 | 说明           |
| -------- | -------- | -------------- |
| ≤30 岁   | 98%      | 年轻人几乎都在世 |
| ≤50 岁   | 90%      | 中年大部分在世   |
| ≤70 岁   | 50%      | 老年生死各半     |
| ≤85 岁   | 15%      | 高龄少数存活     |
| >85 岁   | 2%       | 极少数长寿       |

根据概率决定成员是否有 `death_year`（去世年份），去世者随机在当前年份之前死亡。

#### 2.2.5 输出文件

每个数据集生成 3 个 CSV 文件，共 9 个：

**member.csv** — 成员信息表
```csv
member_id,genealogy_id,name,gender,birth_year,death_year,biography
10001,1,张伟,M,1920,1995,张伟出生于1920年
10002,1,李秀英,F,1922,,李秀英出生于1922年
```
- `death_year`：在世成员此字段为空
- `biography`：自动生成的生平简介

**parent_child.csv** — 父子关系表
```csv
parent_id,child_id,relation_type
10001,10005,father
10002,10005,mother
```
- `relation_type`：`father`（父亲）或 `mother`（母亲）
- 每个孩子有两条记录（一条父亲、一条母亲）

**marriage.csv** — 婚姻关系表
```csv
marriage_id,spouse1_id,spouse2_id,start_date,end_date,status
1,10001,10002,1945-03-15,,active
```
- `start_date`：结婚日期（年份为结婚年份，月日随机生成）
- `end_date`：离婚日期（绝大多数为空）
- `status`：`active`（在婚）或 `divorced`（离异，极少）

#### 2.2.6 确定性随机

使用固定种子（seed）初始化随机数生成器，保证每次使用相同参数生成的数据完全一致，便于调试和复现。

### 2.3 辅助脚本 `generate_django_hash.py`

生成 PBKDF2-SHA256 格式的密码哈希值，与 Django 的 `make_password()` 兼容。用于在 `init.sql` 中预置用户的密码哈希，避免需要通过 Django shell 创建用户。

## 三、SQL 脚本：数据导入

### 3.1 建表：Django Migrations

执行 `python manage.py migrate` 时，Django 根据 `models.py` 自动创建 7 张业务表：

| 表名                      | 用途               | 主键                        |
| ------------------------- | ------------------ | --------------------------- |
| `user`                    | 用户表             | `user_id` (BigAutoField)    |
| `genealogy`               | 族谱表             | `genealogy_id`              |
| `genealogy_user`          | 用户-族谱权限关联  | `genealogy_user_id`         |
| `member`                  | 成员表             | `member_id`                 |
| `parent_child`            | 父子关系表         | `(parent_id, child_id)` 复合主键 |
| `marriage`                | 婚姻关系表         | `marriage_id`               |
| `member_generation_cache` | 代际缓存（性能优化）| `member` (OneToOne FK)      |

关键约束：
- `parent_child` 表：`CHECK (parent_id <> child_id)` — 防止自己是自己的父亲
- `marriage` 表：`CHECK (spouse1_id <> spouse2_id)` — 防止自己和自己结婚
- `genealogy_user` 表：`(user, genealogy)` 唯一约束 — 同一用户在同一族谱中只能有一个角色

索引：
- `member.name`：B-tree 索引 + 前缀索引 `name(10)`
- `parent_child`：`idx_parent`、`idx_child`、`idx_parent_child` 三个索引
- `member_generation_cache`：`(genealogy, generation)` 复合索引

### 3.2 种子数据：`init.sql`

预置最小演示数据，使用 `ON DUPLICATE KEY UPDATE` 保证幂等性（可重复执行）：

```sql
-- 2 个用户（密码为预生成的 PBKDF2 哈希）
INSERT INTO user (user_id, username, password, email, ...) VALUES
(1, 'demo_admin',  'pbkdf2_sha256$...', 'admin@example.com', ...),
(2, 'demo_editor', 'pbkdf2_sha256$...', 'editor@example.com', ...);

-- 1 个族谱
INSERT INTO genealogy (genealogy_id, title, surname, created_by) VALUES
(1, '张氏示例族谱', '张', 1);

-- 绑定权限
INSERT INTO genealogy_user (user_id, genealogy_id, role) VALUES
(1, 1, 'owner'),
(2, 1, 'editor');

-- 6 个成员（3 代人：曾祖→祖→父/母→子/女）
INSERT INTO member (...) VALUES
(1001, 1, '张大山', 'M', 1920, 1990, '...'),  -- 曾祖
(1002, 1, '李翠花', 'F', 1922, 1995, '...'),  -- 曾祖母
(1003, 1, '张建国', 'M', 1948, NULL, '...'),   -- 祖父
```

### 3.3 批量导入：`import_generated.sql`

**这是导入生成数据的核心脚本**，分为 5 个步骤：

#### Step 1：清空旧数据（保留 user 表）

```sql
SET FOREIGN_KEY_CHECKS = 0;  -- 临时禁用外键检查，避免 TRUNCATE 顺序问题
TRUNCATE TABLE parent_child;
TRUNCATE TABLE marriage;
TRUNCATE TABLE member;
TRUNCATE TABLE genealogy_user;
TRUNCATE TABLE genealogy;
SET FOREIGN_KEY_CHECKS = 1;  -- 重新启用外键检查
```

#### Step 2：创建 3 个族谱记录

```sql
INSERT INTO genealogy (genealogy_id, title, surname, created_at, created_by) VALUES
(1, '江氏族谱', '江', NOW(), 1),
(2, '朱氏族谱', '朱', NOW(), 1),
(3, '伍氏族谱', '伍', NOW(), 1);
```

#### Step 3：绑定用户权限

```sql
-- demo_admin 为所有 3 个族谱的 owner
INSERT INTO genealogy_user (user_id, genealogy_id, role) VALUES
(1, 1, 'owner'), (1, 2, 'owner'), (1, 3, 'owner');
-- demo_editor 为 small 和 medium 的 editor
INSERT INTO genealogy_user (user_id, genealogy_id, role) VALUES
(2, 1, 'editor'), (2, 2, 'editor');
```

#### Step 4：LOAD DATA LOCAL INFILE 批量导入

使用 MySQL 的高速批量导入命令，共执行 9 次（3 数据集 × 3 表）：

```sql
-- 导入 small 数据集的成员
LOAD DATA LOCAL INFILE 'sql/generated/small/member.csv'
INTO TABLE member
FIELDS TERMINATED BY ',' ENCLOSED BY '"'
LINES TERMINATED BY '\n'
IGNORE 1 LINES                      -- 跳过 CSV 表头
(member_id, genealogy_id, name, gender, birth_year, @death_year, biography)
SET death_year = NULLIF(@death_year, '');  -- 空字符串转为 NULL

-- 导入 small 数据集的父子关系
LOAD DATA LOCAL INFILE 'sql/generated/small/parent_child.csv'
INTO TABLE parent_child
FIELDS TERMINATED BY ',' ENCLOSED BY '"'
LINES TERMINATED BY '\n'
IGNORE 1 LINES
(parent_id, child_id, @relation_type)
SET relation_type = LOWER(TRIM(@relation_type));  -- 规范化为小写

-- 导入 small 数据集的婚姻关系
LOAD DATA LOCAL INFILE 'sql/generated/small/marriage.csv'
INTO TABLE marriage
FIELDS TERMINATED BY ',' ENCLOSED BY '"'
LINES TERMINATED BY '\n'
IGNORE 1 LINES
(marriage_id, spouse1_id, spouse2_id, @start_date, @end_date, status)
SET start_date = NULLIF(@start_date, ''),
    end_date   = NULLIF(@end_date, '');
```

对 medium 和 large 数据集重复同样操作（路径不同），共 9 次 LOAD DATA。

**LOAD DATA 关键细节**：
- `LOCAL INFILE`：从客户端本地读取文件（非服务器端），需客户端启用 `--local-infile=1`
- `FIELDS TERMINATED BY ','`：CSV 以逗号分隔
- `ENCLOSED BY '"'`：字段用双引号包裹
- `IGNORE 1 LINES`：跳过第一行表头
- `@death_year`：先读入用户变量，再用 `NULLIF` 处理空值
- `LOWER(TRIM(...))`：导入时实时规范化数据

#### Step 5：验证汇总

```sql
SELECT 'member' AS tbl, COUNT(*) AS cnt FROM member
UNION ALL SELECT 'parent_child', COUNT(*) FROM parent_child
UNION ALL SELECT 'marriage', COUNT(*) FROM marriage;
```

预期输出类似：
```
+----------------+-------+
| tbl            | cnt   |
+----------------+-------+
| member         | 55500 |
| parent_child   | 98700 |
| marriage       | 42300 |
+----------------+-------+
```

## 四、SQL 查询执行方式

项目中的 SQL 通过两种方式执行：

### 4.1 Django ORM（适用于简单 CRUD）

```python
# 查找某个族谱的所有成员
members = Member.objects.filter(genealogy_id=genealogy_id)

# 创建新成员
Member.objects.create(
    genealogy_id=genealogy_id,
    name="张三",
    gender="M",
    birth_year=1990
)
```

### 4.2 原生 SQL + cursor.execute（适用于复杂查询）

```python
# 递归 CTE 查找所有祖先
with connection.cursor() as cursor:
    cursor.execute("""
        WITH RECURSIVE ancestors AS (
            -- 锚点：从指定成员开始
            SELECT parent_id, child_id, relation_type, 1 AS depth
            FROM parent_child
            WHERE child_id = %s

            UNION ALL

            -- 递归：向上追溯
            SELECT pc.parent_id, pc.child_id, pc.relation_type, a.depth + 1
            FROM parent_child pc
            JOIN ancestors a ON pc.child_id = a.parent_id
            WHERE a.depth < 10
        )
        SELECT DISTINCT m.*
        FROM ancestors a
        JOIN member m ON m.member_id = a.parent_id
        ORDER BY a.depth
    """, [member_id])
    rows = cursor.fetchall()
```

项目中大量使用原生 SQL 的原因：递归 CTE、复合主键、UNION ALL 等高级 SQL 特性在 Django ORM 中支持有限或写法笨拙，直接写 SQL 更清晰高效。

## 五、性能优化

项目在数据量较大时遇到了严重的性能问题，经过针对性优化后得到显著改善：

| 查询               | 优化前          | 优化后           | 优化方法                           |
| ------------------ | --------------- | ---------------- | ---------------------------------- |
| 分析页面加载        | 3.4s / 18MB     | 55ms / 176KB     | 按族谱筛选成员，上限 500 条         |
| Q3 最长寿代际       | 14.8s           | 0.16s            | 代际缓存表（BFS 预计算）            |
| Q4 未婚男性>50岁    | 121.8s          | 0.26s            | CTE + anti-join 替代 OR 条件 JOIN  |
| Q5 早生成员         | 14.7s           | 0.50s            | 代际缓存表                         |

核心优化手段是 `member_generation_cache` 表——通过 BFS（广度优先搜索）预计算每个成员的代际编号并缓存，避免每次查询都执行昂贵的递归 CTE。缓存在成员数量变化时自动惰性重建。
